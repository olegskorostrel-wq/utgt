# Полная проверка сайта

Цель — найти как можно больше ошибок и исправить их. Время не важно: лучше прогнать лишний раз.
Общаться по-русски, коротко, без английских слов (см. CLAUDE.md). Пользователю — только итог и вопросы.

## 0. Подготовка

- `git pull origin main`. Посмотреть, что менялось с прошлого раза: `git log --oneline -30`.
- Поставить себе список шагов (задачи) и идти по нему, отмечая сделанное.

## 1. Без браузера

1. `python3 -m pytest -q`
2. `for f in tests/*.test.js; do node $f; done`
3. `python3 tools/check_data.py` — ошибки обязательно разобрать; предупреждения просмотреть.
4. `python3 tools/publish_times.py` — нет ли поздних распоряжений (если много — сказать пользователю).
5. Прочитать глазами код, изменённый за последние коммиты (`git diff HEAD~15 -- site/ tools/ scraper.py`):
   ошибки на краях (пустые данные, нет интернета, неправильный адрес, выходной, каникулы, первый заход
   без сохранённого), забытые обработчики, утечки таймеров, тексты на английском, данные людей в публичном репозитории.

## 2. В браузере — весь набор

`bash tests/browser/run.sh` — собирает сайт, поднимает его локально и гоняет все проверки
(`tests/browser/01…10`). Полный вывод каждой — в `_proverka/<имя>.txt`, сводка — `_proverka/svodka.txt`.

| № | Что проверяет |
|---|---|
| 01 | Пары на экране = расчёт: все группы × все дни с заменами, неделя вперёд, каникулы, практики, праздники; обе подгруппы |
| 02 | Расписание каждого преподавателя = расчёт по всем группам и заменам |
| 03 | Подсказки «Ауд. …: этаж» у всех групп; кабинеты без этажа |
| 04 | Вёрстка: все группы × сегодня/завтра/неделя × 9 ширин (280…1920) + крупный масштаб, всё раскрыто, окна |
| 05 | Быстрые нажатия (1…7 подряд) на всё раскрывающееся — итог верный, ничего не вылезает |
| 06 | Стресс: тысячи случайных нажатий, клавиш, свайпов на телефоне и компьютере |
| 07 | Каждая функция по отдельности: выбор группы/преподавателя, история, «i», значок интернета, метки, «где преподаватель», змейка, свайпы, тема, подгруппа, неправильные адреса, счётчик |
| 08 | Без интернета, медленная сеть, новая версия применяется сама, подсказки установки в 7 браузерах |
| 09 | Скорость на слабом интернете (первый и повторный заход) |
| 10 | Код страницы: синтаксис, данные читаются, все id на месте, файлы и ссылки целы, нет ключей, описания картинок и кнопок |

Стресс-тест (06) прогнать **трижды** (каждый раз со своим «зерном» внутри; можно `STEPS=1500`).
Отдельные проверки: `bash tests/browser/run.sh 04 07`.

Пока сайт собирается и проверяется, **не пересобирать `_site`** — иначе проверка поймает ложные ошибки.

## 3. Разобрать найденное

Для каждой находки: воспроизвести вручную (маленький скрипт Playwright), понять — ошибка сайта или самой
проверки.
- Ошибка сайта → исправить, перезапустить ту проверку, что её нашла, и соседние.
- Ошибка проверки → поправить проверку в `tests/browser/` (чтобы в следующий раз не мешала).
- Спорное оформление или новое поведение → не делать молча, спросить пользователя.

Если появилась новая функция сайта, а проверки на неё нет — дописать её в нужный файл (обычно 07).

## 4. Выложить и проверить живой сайт

1. Всё из раздела «Перед тем как выкладывать» в CLAUDE.md.
2. `git push origin main`, дождаться обновления (метка `app.js?v=` на живом сайте = в `_site`).
3. `bash tests/browser/run.sh --live` — те же проверки на настоящем сайте.

## 5. Вокруг сайта

- GitHub Actions: последние запуски `update.yml` — нет ли упавших; идут ли запуски от сторожа
  (`workflow_dispatch` в течение дня). Если сторож молчит больше суток при новых заменах — сказать.
- `data/health.json` — нет ли подряд идущих сбоев проверки замен.
- Открытые задачи в репозитории (сообщения из бота) — нет ли жалоб на ошибки.
- Таблица счётчика на Гугл Диске (почта сайта) — пишутся ли строки за последние дни.

## 6. Отчёт пользователю

Коротко, по-русски, без английских слов:
- сколько всего проверено (страниц, нажатий, экранов);
- что нашлось и исправлено (по пунктам, простыми словами);
- что нашлось, но не исправлено, и почему (или вопрос пользователю);
- что ещё стоит сделать.
